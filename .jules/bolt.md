## 2024-08-15 - Double-Checked Locking for Promise Mutexes
**Learning:** Promise-based mutex queues (like `ensureFolderMutex = next; await prev;`) create severe event-loop bottlenecks under high concurrency if they lack a synchronous fast-path. Even if the awaited operation within the lock is extremely fast or already cached, pushing every call onto the end of the promise chain queue forces the JavaScript engine to yield the current execution context and serialize operations that could otherwise run in parallel.
**Action:** Always implement the Double-Checked Locking pattern for I/O caches protected by a promise queue. Perform a synchronous fast-path check against the in-memory cache *before* awaiting the mutex queue, and repeat the check *after* acquiring the lock to prevent race conditions.
