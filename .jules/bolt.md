## 2024-08-13 - [SyncEngine ensureFolder mutex bottleneck]
**Learning:** The `ensureFolder` method in SyncEngine uses a mutex to serialize folder creation, preventing race conditions. However, it acquired this mutex unconditionally before checking the memory cache (`this.folderCache`) or the Obsidian vault (`this.vault.getAbstractFileByPath`). Since `ensureFolder` is called concurrently for every block asset (via `pMap`), this unconditionally serialized all asset processing at the mutex level, negating the benefits of concurrency when the folder already exists.
**Action:** Implemented the Double-Checked Locking pattern. Always check the fast, synchronous memory cache and vault state *before* acquiring the mutex. If a cache miss occurs, acquire the mutex, then check again before proceeding. This allows concurrent blocks to instantly bypass the mutex when the folder already exists, significantly improving sync performance for large channels.
